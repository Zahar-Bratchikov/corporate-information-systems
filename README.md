# ИС УПЗ IT — Информационная система управления проектами и задачами в IT

Система планирования и учёта IT-проектов, управления задачами (фичи, баги, технические задачи), распределения нагрузки и формирования отчётности. Реализована на **ASP.NET Core** (backend), **React** (frontend), **PostgreSQL** (БД). Полное развёртывание в **Docker**.

## Требования

- Docker и Docker Compose
- Для локальной разработки: .NET 8 SDK, Node.js 20+, PostgreSQL 16

## Развёртывание в Docker

1. Клонируйте репозиторий и перейдите в каталог проекта.

2. Запустите все сервисы:
   ```bash
   docker-compose up --build
   ```

3. При первом запуске:
   - Контейнер **db** (PostgreSQL) создаёт БД и выполняет схему из `database/init/01-schema.sql`.
   - Контейнер **backend** при старте подключается к БД и заполняет тестовые данные (роли, пользователи, проекты, задачи и т.д.) через встроенный сидер.
   - Контейнер **frontend** собирает React-приложение и раздаёт его через nginx; запросы к `/api/` проксируются на backend.

4. Откройте в браузере: **http://localhost:18080** (веб-интерфейс).

5. Учётные данные тестовых пользователей (пароль у всех один):

## Сервисы и порты

| Сервис    | Порт (хост) | Описание                          |
|-----------|-------------|-----------------------------------|
| frontend  | 18080       | SPA (React), nginx                |
| backend   | 8080        | REST API (ASP.NET Core)           |
| db        | — (внутренняя сеть Docker) | PostgreSQL                        |

Подключение к БД из backend задаётся переменной окружения `ConnectionStrings__DefaultConnection` (в docker-compose указывается хост `db`).

## Локальная разработка

### База данных

Поднимите PostgreSQL (или используйте контейнер только для БД):

```bash
docker-compose up -d db
```

Примените схему (если ещё не применена):

```bash
docker compose exec -T db psql -U upzit -d upzit -f /docker-entrypoint-initdb.d/01-schema.sql
```

### Backend

```bash
cd backend
dotnet run
```

API будет доступен по адресу http://localhost:5000 (или порт из launchSettings). При первом запуске сидер заполнит БД тестовыми данными.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Запросы к `/api` проксируются на backend (настройка в `vite.config.ts`).

## Функциональность

- **Авторизация:** вход по логину и паролю, JWT, роли (Администратор, Руководитель/Тимлид, Разработчик/QA, Наблюдатель).
- **CRUD:** проекты, задачи, пользователи (только админ), спринты, справочники (типы задач, статусы, приоритеты).
- **Права:** админ — полный доступ; руководитель — проекты/задачи/спринты; разработчик/QA — свои задачи и отчёты; наблюдатель — только просмотр и отчёты.
- **Пять отчётов** с экспортом и **просмотром в браузере** (превью JSON: `GET /api/reports/previews/...`, кнопка «Показать в приложении» на странице «Отчёты»):
  1. Сводный по IT-проектам — Excel, PDF  
  2. Задачи исполнителя с итогами — Excel, Word, PDF  
  3. Просроченные задачи — Excel, PDF  
  4. Загрузка команды (опционально по спринту) — Excel, Word  
  5. Статусы IT-проектов — Word, PDF  

## Структура проекта

- `backend/` — ASP.NET Core API (контроллеры, сервисы, сущности, DTO, DbContext).
- `frontend/` — React SPA (Vite, TypeScript), страницы: вход, проекты, задачи, пользователи, спринты, отчёты.
- `database/init/` — SQL-скрипт инициализации схемы БД для Docker.
- `docs/` — ТЗ, архитектура, модель БД.

## Остановка

```bash
docker-compose down
```

Данные PostgreSQL сохраняются в volume `postgres_data`. Для полного удаления с данными:

```bash
docker-compose down -v
```
