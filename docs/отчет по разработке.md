
## 1. Постановка задачи

### 1.1. Описание назначения КИС и основного функционала согласно ТЗ

Согласно техническому заданию (файл `docs/specifications.md`), **информационная система управления проектами и задачами в IT (ИС УПЗ IT)** предназначена для применения в IT-подразделениях: планирование и учёт IT-проектов и релизов, управление задачами (фичи, исправления, технические задачи), распределение нагрузки между исполнителями, контроль сроков и формирование отчётности.

**Основной функционал по ТЗ:**

- ведение данных по **IT-проектам**, **задачам**, **пользователям** и ролям, **спринтам**, справочникам (типы задач, статусы, приоритеты), назначение исполнителей, привязка задач к проектам и спринтам;
- **авторизованный доступ** с разграничением прав по ролям: администратор, руководитель проекта / тимлид, разработчик / QA, наблюдатель;    
- **не менее пяти отчётов** с выгрузкой в форматы **MS Excel (.xlsx), MS Word (.docx), PDF** в соответствии с перечнем в ТЗ;
- **валидация данных** и реакция на ошибочный ввод и несанкционированный доступ;
- эксплуатация в корпоративной среде с возможностью **развёртывания в Docker**.

Подробное описание отчётов и полей приведено в разделе 4.1 ТЗ (`docs/specifications.md`).

### 1.2. Цель работы и задачи для её достижения

**Цель работы:** спроектировать и реализовать работоспособный программный комплекс ИС УПЗ IT в соответствии с ТЗ: клиент-серверная архитектура, реляционная БД, веб-интерфейс, REST API, отчёты в файловых форматах, разграничение доступа.

**Задачи:**

1. Разработать и применить **модель данных** (схема БД, связи сущностей).
2. Реализовать **backend** — REST API, бизнес-логика, авторизация (JWT), проверка прав, формирование отчётов.
3. Реализовать **frontend** — SPA: вход, работа с проектами, задачами, пользователями, спринтами, отчётами; удобный и тестируемый интерфейс.
4. Обеспечить **развёртывание** через Docker Compose (БД, API, статика фронтенда).
5. Подготовить **документацию** API и рекомендации по тестированию; по возможности — unit-тесты.

## 2. Реализация

### 2.1. Средства, среда разработки и используемые фреймворки

| Компонент           | Технологии                                                                                                                                                                          |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **База данных**     | PostgreSQL 16, скрипт инициализации `database/init/01-schema.sql`                                                                                                                   |
| **Backend**         | C#, **.NET 8**, **ASP.NET Core Web API**, Entity Framework Core, JWT (Bearer), BCrypt для хешей паролей; библиотеки для отчётов: ClosedXML (Excel), QuestPDF (PDF), Open XML (Word) |
| **Frontend**        | **TypeScript**, **React 18**, **Vite**, **React Router v6**; обращение к API через `fetch`                                                                                          |
| **Контейнеризация** | **Docker**, **Docker Compose** (`docker-compose.yml`): сервисы `db`, `backend`, `frontend` (сборка SPA + nginx)                                                                     |
| **Тестирование**    | Backend: xUnit, Moq, EF InMemory (`backend/UpzIt.Api.Tests`); Frontend: **Vitest**, Testing Library (`frontend`)                                                                    |
| **Документация**    | `docs/API.md`, `docs/TESTING.md`, `docs/TESTS.md`, `README.md`                                                                                                                      |

Исходный код: `backend/` (проект `UpzIt.Api`), `frontend/` (Vite-приложение), `database/init/`.

#### 2.2.2. Функционал (вид) ИС под разными пользователями

Роли из ТЗ реализованы через проверку на backend и ограничение UI на frontend (`canEdit`, `isAdmin`, скрытие пунктов меню).

|                           |                                                                              |
| ------------------------- | ---------------------------------------------------------------------------- |
| Роль                      | Отличия в интерфейсе (примерно)                                              |

#### 2.2.3. Редактирование информационной составляющей БД

**В приложении:** формы и таблицы на страницах «Проекты», «Задачи», «Пользователи», «Спринты» — создание, изменение, удаление (где разрешено политикой). Данные загружаются через REST (`/api/projects`, `/api/tasks`, `/api/users`, `/api/sprints`, справочники `/api/reference-data/...`).

## 3. Вывод

### 3.1. Что сделано

Реализована **ИС УПЗ IT** в объёме, заявленном в репозитории: **PostgreSQL**, **ASP.NET Core 8 API** с JWT и ролями, **React SPA**, **пять видов отчётов** с экспортом в Excel, Word и PDF, **Docker Compose** для запуска всего стека.

### 3.2. Плюсы и минусы; полнота реализации

**Плюсы:**

- чёткое разделение frontend / backend / БД;
- соответствие ТЗ по ролям, CRUD, отчётам и форматам;
- документированное API и тестовые селекторы UI;
- возможность развернуть в docker

**Минусы и ограничения:**

- нет полноценных **e2e-тестов** ;
- нет поддержки **https**


**Итог по ТЗ:** основной функционал реализован.
